## 底栏动画 bug 修复（冷启动闪 + 连点错乱）
- 根因 1（连点动画错乱）：悬浮 tabBar 的胶囊位置 / 选中态之前存在**每个页面各自的实例**里，
  被切走的实例收不到更新 → 页面再显示时先在旧位置画一帧再被拉回。
  **改法**：真相搬到 `utils/tab-slide.js` 的模块级共享状态（watchTabUI / moveIndicator /
  highlightTab / settleTab），所有实例订阅 → 隐藏实例也同步，第一帧即正确。
  顺带把切换页的"连点保护"从实例级 350ms 锁换成 `scheduleNav`（可被"改主意"覆盖、只切一次）。
  旧的 `lastIndex / __sliding / __navLock / pending / indAnim / no-anim` 全部移除。
- 根因 2（冷启动首次切页闪）：新建页面 onShow 早于首帧绘制，离场态（透明）与归位值被合并进
  同一批 patch，过渡没有起点 → 内容"啪"地蹦出。`tab-slide-mixin.js` 的 `enter()` 现在用
  `afterPaint`（双 rAF + setTimeout 兜底）等浏览器画过离场帧再下发归位值。
- 校验脚本已同步：`_tools/check-tabbar.js`、`_tools/check-tab-slide.js`。全量 64 个脚本 0 失败。

## 不背单词机制：记错了 + 多次确认
- **需求**：① 答对后可反悔（防手滑/蒙对溜过去）；② 一遍答对不算学会，多次确认才计入进度。
- 新增 `word-session.createConfirmSession(deck, {review})`（纯逻辑）：
  `CONFIRM_TIMES=2`，队列制 —— 答对 streak+1，达标（need）才 done+1（= 页面进度条分子）；
  答错清零、`need` 升级为 2；重新入队插到**第 3 位**（隔两个词再回头，防瞬时记忆）；
  `markWrong(id)` 撤销已计入的 done。**复习首答对即算记住（need=1），答错升级为完整确认**。
- 新增 `engine.revokePass(q,...)` + `iplus1.revokeMastery(bookId, wordIds)`：把刚记的 pass 改判 fail。
  净效果 m-3（撤销 +1 再 -2）、今日 total 不变 correct-1、进错题本。**不复用 recordAnswer 的 fail
  分支**（那会 total+1，一题记两次）。
- **word-drill**：进度条改为 doneCount/total（会一个 +1）；第二次见到词标「再确认」紫标；
  答对后结果卡有「记错了」→ revoke + session.markWrong + 进度回退；总结显示"共作答 N 次 · 答错 M 次"。
- **practice**：finish 拆成「确认 → commit」：句子答对且非 review 且有目标词 → 弹「这个词什么意思」
  四选一（`wordSession.toItem` 本地生成，零 AI 成本），确认对了才 pass；确认错 → 整题按 fail 落账。
  **确认期间藏参考答案/词义 chips/AI 点评**（chips 里就是答案，会泄题）。答对后有「记错了」按钮。
- 校验扩展：check-word-drill 第 11-13 组（假词表驱动会话状态机 + revoke 记账语义 + 页面契约）、
  check-practice 第 9 组。全量 66 个脚本 0 失败。
- 坑：check-word-drill 的页面契约要求 `setupQuestion(i)` 保留**索引签名**（第 10 组直接拿索引调），
  会话驱动另走 `setupByItem(item)`（questions.indexOf 取索引）。

## 进度条再改：上面那条改累计 + 两条配色可开关
- **上面那条「已做」= 累计作答次数，没有上限、不带分母**：确认机制下刷单词会来回确认，
  次数必然超过组词数，写"x / 组词数"就被卡住了。改法：
  · `answerCount` 只增不减（改判也不回退 —— 做了就是做了），`answerText` = 'N 题' / 'N 题 · 第 M 轮'
  · 进度条按"每做完一轮（= 本组题量/词数）"**循环填充**：`inLap = n % cap`，
    n 是 cap 整数倍且 >0 时给满格（否则刚好做完一轮会显示 0%）；轮次 = `floor((n-1)/cap)+1`
  · practice 里一次 finish = 一次作答（确认题不算新的一次，commit 也不额外 +1）
- **配色可开关**：`settings.theme.progressSync`（默认 true），唯一读取口 `theme.barsSyncColors()`
  （只有显式 false 才算"分开"，脏值回落 true）。页面根节点 `:class="barsSync ? 'sync' : 'split'"`
  + CSS 两套规则：sync = 已做 `rgba(var(--brand-rgb),.38)` 浅版 / 已会 `var(--brand)` 实心；
  split = 已做 `var(--brand)` / 已会绿色。**全部走 CSS 变量** → 换主题色、切深色模式自动跟随，
  不写死色值。两个页面在 `onShow` 里重读开关（从设置页返回即生效）。
- **设置页**（外观 → 练习进度条）：加了开关 + 两条同款预览（`pg-fill-done.sync` 特异性高于
  `.pg-fill-done`，所以 sync 覆盖默认）。预览的颜色规则和练习页完全一致。
- 校验：check-word-drill 第 13 组（累计/循环/配色 class 与 CSS 变量）+ 第 14 组重写
  （第一轮 3 次 → 满格；第 4 次进入第二轮 → 33% + "第 2 轮"；两轮累计 6 > 组词数 3；
  改判后"已做"不回退）；check-practice 第 10 组（累计口径 + spy 记笔数）；
  check-theme 新增 6b（开关默认/显式关/脏值回落/defaults 里有这个键）。
  全量 66 个脚本 0 失败。
- 坑：check-word-drill 只有 `is/eq`，**没有 `assert`**（是 check-home 才有），
  照抄会 ReferenceError；数横条要用 `/class="wd-bar (?:done|know)"/` 这种精确正则
  （`/class="wd-bar/` 会把 .wd-bar-k / .wd-bar-v 一起数进去，2 变 6）。
